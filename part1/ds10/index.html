1왜 필요한가

09장의 불편은 전부 한 곳에서 나왔다 — 뒤로만 갈 수 있다. 이 장은 배열 하나를 더 두어 그 제약을 없앤다. 노드당 8바이트가 12바이트가 되고, 대신 할 수 있는 일이 크게 늘어난다.

1.1 “이 노드를 지워라”가 09장에서는 O(N)이었다

09장에서는 지울 노드의 번호를 이미 알아도 앞 노드가 따로 주어지지 않았다면 보통 앞 노드를 탐색해야 했다. 단일 연결 리스트에서 nxt[?] = …를 고치려면 그 앞 노드가 필요한데, prv가 없어 맨 앞부터 찾으면 O(N)이 된다. 맨 앞 노드를 지우거나 앞 노드를 이미 아는 경우에는 단일 연결 리스트도 O(1)이다.

$ ./erase      노드 번호를 알고 있는 상태에서 n개를 전부 지운다

[앞에서부터 지울 때]
        n   단일(ms)     단일 이동량   이중(ms)   이중 이동량
   100000        0.1         100,000        0.4       200,000     ← 단일도 빠르다

[뒤에서부터 지울 때 — 순서만 바꿨다]
   100000    10156.5   5,000,050,000        0.3       200,000     ← 약 34,000배

08장에서 본 것과 똑같은 함정

같은 코드, 같은 개수인데 지우는 순서만 바꿨더니 0.1 ms가 10초가 되었다. 앞에서부터 지우면 매번 더미 바로 다음이라 한 걸음이면 되지만, 뒤에서부터면 매번 끝까지 걸어야 한다. 출제자는 뒤에서부터 지우는 입력을 넣는다.

1.2 배열 하나를 더 두면 끝난다

/* 09장 — 단일 */
int val[N];
int nxt[N];

/* 지우려면 앞 노드를 찾아야 */
int p = find_prev(x);   /* O(N) */
nxt[p] = nxt[x];
/* 10장 — 이중 */
int val[N];
int prv[N], nxt[N];

/* 앞 노드를 이미 알고 있다 */
nxt[prv[x]] = nxt[x];   /* O(1) */
prv[nxt[x]] = prv[x];

find_prev가 사라지고 두 줄이 남는다. 이 두 줄이 이 장의 거의 전부다.

2.2 센티넬 두 개 — 검사가 통째로 사라진다

09장의 더미 헤드는 맨 앞의 특수 처리를 없앴다. 이중 연결에서는 맨 뒤도 특수한 경우가 되므로, 센티넬을 양쪽에 하나씩 둔다. 그러면 놀라운 일이 생긴다.

센티넬이 없으면

void erase(int x){
    if (prv[x] != NIL) nxt[prv[x]] = nxt[x];
    else               head = nxt[x];
    if (nxt[x] != NIL) prv[nxt[x]] = prv[x];
    else               tail = prv[x];
}

센티넬 두 개면

void erase(int x){
    nxt[prv[x]] = nxt[x];
    prv[nxt[x]] = prv[x];
}

if가 하나도 없다. prv[x]와 nxt[x]가 언제나 존재하기 때문이다.

왜 항상 존재하는가

진짜 노드는 HEAD와 TAIL 사이에만 놓인다. 따라서 어떤 진짜 노드 x를 잡아도 왼쪽에는 노드가 있고(최소한 HEAD), 오른쪽에도 있다(최소한 TAIL). 빈 리스트든 노드가 하나든 백만 개든 똑같다. 06장부터 반복해 온 “특수한 경우를 없애는 설계”가 가장 깔끔하게 드러나는 자리다. 단, 삭제 대상이 실제로 연결된 데이터 노드인지, 새 노드를 만들 공간이 남았는지는 호출자가 확인해야 한다.

Q. 센티넬 두 개면 메모리가 두 칸 더 드는데 괜찮나요?
노드 하나가 12바이트이므로 24바이트다. 100만 노드짜리 문제에서 12 MB를 쓰는데 그중 24바이트다. 끝점 예외 처리 분기들을 24바이트로 줄이는 것이고, 분기 하나는 버그 하나다.

2.3 커서 — 정수 하나로 표현한다

글자들 사이를 오가는 깜빡이는 막대를 자료구조로 어떻게 표현할까. 커서는 글자가 아니라 글자와 글자 사이에 있으므로, “몇 번째 글자”로는 어색하다. 규칙 하나로 해결한다.

약속

cur은 “커서 바로 오른쪽에 있는 노드”의 번호다. 커서가 맨 끝에 있으면 cur = TAIL이다.

명령뜻코드경계
L커서를 왼쪽으로cur = prv[cur]prv[cur]==HEAD면 무시
D커서를 오른쪽으로cur = nxt[cur]cur==TAIL이면 무시
B왼쪽 글자 지우기erase(prv[cur])prv[cur]==HEAD면 무시
P x커서 왼쪽에 x 삽입insert_before(cur, x)경계 없음

네 명령 모두 O(1)이다. 커서가 어디에 있든, 문자열이 얼마나 길든 상관없다. B가 가능한 것은 prv가 있기 때문이다 — 09장의 단일 연결로는 왼쪽 글자를 지울 수 없다.

2.4 원형 연결 — 센티넬마저 없앤다

요세푸스처럼 끝이 없는 문제에서는 마지막을 처음에 이어 고리로 만든다. 그러면 “끝”이라는 개념 자체가 없으므로 센티넬도 필요 없다.

for (int i = 1; i <= n; i++) {
    nxt[i] = (i == n) ? 1 : i + 1;      /* 마지막의 다음은 1번 */
    prv[i] = (i == 1) ? n : i - 1;      /* 1번의 앞은 마지막 */
}

대신 조심할 것

끝이 없으므로 순회를 멈추는 조건을 따로 만들어야 한다. 남은 개수를 세거나, 출발점을 기억해 두고 돌아왔는지 본다. 조건을 빼먹으면 09장 연습 04처럼 무한 루프가 된다.

3.1 DList — 필수 구현

/* dlist.c — 0번 HEAD, 1번 TAIL. 두 센티넬을 사용 */
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>
#define MAXNODE 1000006
static int val[MAXNODE], prv[MAXNODE], nxt[MAXNODE];
static int cnt, HEAD, TAIL;

static int new_node(int v){
    if (cnt >= MAXNODE) { fputs("node pool full\n", stderr); exit(1); }
    val[cnt] = v;  prv[cnt] = nxt[cnt] = -1;
    return cnt++;
}
static void dl_init(void){
    cnt = 0; HEAD = new_node(0); TAIL = new_node(0);
    nxt[HEAD] = TAIL;  prv[TAIL] = HEAD;
}
/* 전제: x는 연결된 노드 또는 TAIL, HEAD는 아님 */
static int insert_before(int x, int v){
    assert(x >= TAIL && x < cnt);
    int p = prv[x], q = new_node(v);
    prv[q] = p;  nxt[q] = x;  /* 원래 이웃 번호를 보존 */
    nxt[p] = q;  prv[x] = q;
    return q;
}
/* 전제: x는 현재 연결된 실제 노드, 센티넬 아님 */
static void erase(int x){
    assert(x > TAIL && x < cnt);
    nxt[prv[x]] = nxt[x];
    prv[nxt[x]] = prv[x];
}

링크를 고치는 순서 — p 저장 여부가 핵심

이 코드에서는 p = prv[x]를 먼저 저장했으므로 새 노드와 이웃에 대한 네 대입의 순서를 바꾸어도, 필요한 기존 이웃 번호를 유지한다면 정상 연결된다. 그러나 p를 저장하지 않고 prv[x] = q를 먼저 실행한 뒤 다시 prv[x]를 앞 노드로 읽으면, 이미 q로 바뀐 값이어서 연결이 깨진다. 권장 습관은 기존 이웃 번호를 먼저 저장하고, 새 노드의 링크를 먼저 기록한 뒤 이웃을 고치는 것이다.

$ ./dlist
빈 리스트          H <-> T
맨 뒤로 10,20,30   H <-> 10 <-> 20 <-> 30 <-> T
맨 앞에 5          H <-> 5 <-> 10 <-> 20 <-> 30 <-> T
20 앞에 15         H <-> 5 <-> 10 <-> 15 <-> 20 <-> 30 <-> T
뒤에서부터 읽기    T <-> 30 <-> 20 <-> 15 <-> 10 <-> 5 <-> H   ← 역방향 링크로 별도 역전 없이 순회

  i   :    0    1    2    3    4    5    6
  val :    0    0   10   20   30    5   15
  prv :   -1    4    5    6    3    0    2
  nxt :    5   -1    6    4    1    2    3

erase(3) — 값 20인 노드를 직접 지운다 (앞 노드를 찾지 않는다)
지운 뒤            H <-> 5 <-> 10 <-> 15 <-> 30 <-> T

역순 순회를 위한 별도의 뒤집기 과정이 필요 없다. 09장에서는 리스트를 거꾸로 읽으려면 통째로 뒤집어야 했는데, 여기서는 prv를 따라가면 그만이다.

3.2 커서 에디터

2.3절의 표를 그대로 코드로 옮긴다. 분기는 경계 처리 세 개뿐이고, 나머지는 한 줄씩이다. 입력에서 초기 문자열을 구성하고 명령을 읽는 부분은 생략한 핵심 로직이며, 실행 가능한 전체 프로그램은 별도 C 파일에 수록한다.

int cur = TAIL;                       /* 커서는 처음에 맨 끝 */

for (int i = 0; i < m; i++) {
    switch (cmd[i]) {
    case 'L': if (prv[cur] != HEAD) cur = prv[cur];          break;
    case 'D': if (cur      != TAIL) cur = nxt[cur];          break;
    case 'B': if (prv[cur] != HEAD) erase(prv[cur]);          break;
    case 'P': insert_before(cur, arg[i]);                     break;
    }
}
/* 출력은 HEAD 다음부터 TAIL 전까지 */
for (int p = nxt[HEAD]; p != TAIL; p = nxt[p]) putchar(val[p]);

세 가지를 확인한다

  • B가 erase(prv[cur])이다. 커서 왼쪽 글자를 지운다. 단일 연결 리스트에서는 앞 노드를 따로 저장하지 않았다면 O(1)로 직접 삭제할 수 없고, 처음부터 찾아야 한다.
  • P에는 경계 검사가 없다. cur이 TAIL이어도 “TAIL 앞에 삽입”이 곧 맨 뒤 추가다 — 센티넬의 효과
  • 커서는 삽입·삭제 뒤에도 그대로 둔다. P는 왼쪽에 넣으므로 커서 오른쪽 노드가 안 바뀌고, B는 왼쪽을 지우므로 역시 안 바뀐다

3.3 요세푸스 — 원형 연결

이 코드는 2.4절에서 1~N번을 원형으로 연결한 뒤 실행한다. 3.1절의 HEAD·TAIL 센티넬 리스트와는 별개로 초기화해야 한다. 조건은 N ≥ 1, K ≥ 1이다.

int cur = 1, m = 0;
while (m < n) {
    for (int s = 1; s < k; s++) cur = nxt[cur];   /* k-1 칸 이동 */
    out[m++] = cur;                                /* 이번에 제거될 사람 */
    int after = nxt[cur];                          /* 먼저 붙잡는다 */
    nxt[prv[cur]] = nxt[cur];                      /* O(1) 제거 */
    prv[nxt[cur]] = prv[cur];
    cur = after;                                   /* 지워진 자리의 다음부터 */
}
$ ./jose      N = 7, K = 3
3번 제거 → 다음 시작 4
6번 제거 → 다음 시작 7
2번 제거 → 다음 시작 4
7번 제거 → 다음 시작 1
5번 제거 → 다음 시작 1
1번 제거 → 다음 시작 4
4번 제거 → 종료
결과 : 3 6 2 7 5 1 4

제거된 노드의 nxt는 그대로 남아 있다

위 코드에서 after를 먼저 저장했지만, 사실 erase는 지워지는 노드 자신의 prv·nxt를 건드리지 않는다. 그래서 지운 뒤에 nxt[cur]을 읽어도 값은 멀쩡하다. 이 성질이 도전 C2(되살리기)의 열쇠가 된다 — 다만 의도해서 쓰는 것과 모르고 의존하는 것은 다르다.

이 표에서 반드시 읽어야 할 것

  • n이 5배가 되자 배열은 44배 느려졌다(5.1 → 222.3 ms). 전형적인 O(N²)
  • 리스트와 두 스택은 거의 같다. 같은 문제를 전혀 다른 자료구조로 똑같이 빠르게 풀 수 있다 — 도전 C1

그런데 이동량과 시간이 비례하지 않는다 — 02장의 단서를 다시 본다

n = 100만에서 이동량은 149억 대 89.7만으로 약 16,600배 차이인데, 시간은 222.3 대 9.2로 24배밖에 나지 않았다. 왜일까.

배열이 미는 작업은 memmove로 연속된 메모리를 통째로 옮긴다. CPU는 이런 일을 한 번에 수십 바이트씩 처리하므로 “이동 한 번”이 거의 공짜다. 반면 리스트는 연산 한 번이 여기저기 흩어진 메모리를 건드리는 일이라 한 번이 비싸다(09장 4.3절, 48배). 결론 — 연산 횟수는 복잡도를 보는 도구이지 시간을 예측하는 도구가 아니다. 그래도 n이 커지면 O(N²)은 반드시 진다.

“이중이면 k번째도 빨라지겠지”임의 접근은 여전히 O(N)이다이중이 바꾸는 것은 “왼쪽을 알아야 하는 일”뿐 (4.1절)
“센티넬은 번거롭다”erase에만 분기가 네 개 생긴다연습 02에서 직접 세어 본다
“앞 노드 번호를 저장하지 않고 링크를 덮어써도 되겠지”덮어쓴 prv[x]를 다시 앞 노드로 읽으면 연결이 깨진다먼저 p=prv[x]를 저장하고, 새 노드의 링크부터 기록하는 습관을 들인다
“커서는 몇 번째 글자다”커서는 글자 사이에 있다cur = 오른쪽 노드 번호로 약속한다 (2.3절)
“P 뒤에 커서를 옮겨야겠지”왼쪽에 넣으므로 오른쪽 노드가 안 바뀐다보정 코드를 넣으면 오히려 틀린다 (예제 2)
“원형이면 코드가 더 간단하네”끝이 없어 멈출 조건을 따로 만들어야 한다남은 개수를 센다 (3.3절)
“이동량이 1만 배면 1만 배 느리다”memmove는 매우 빠르다 — 16,600배 대 24배연산 횟수는 복잡도를 보는 도구다 (3.4절)
“작은 입력에서 배열도 되던데”n = 20만에서는 빨라 보여도 100만에서는 훨씬 느려진다 (통과 여부는 제한 시간에 따라 다름)최대 입력으로 테스트한다

자가 점검

  • erase를 두 줄로, 검사 없이 쓸 수 있다
  • 센티넬 두 개가 양 끝 NIL 분기를 왜 없애는지 설명할 수 있다
  • insert_before 네 줄의 순서를 틀리지 않는다
  • 커서를 노드 번호로 표현하고 네 명령을 O(1)로 짤 수 있다
  • 원형 연결을 만들고 멈출 조건을 넣을 수 있다
  • 배열·단일·이중의 복잡도 표 여섯 줄을 채울 수 있다
  • 이동량과 실제 시간이 왜 다른지 설명할 수 있다
