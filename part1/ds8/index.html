1왜 필요한가

이 장은 두 가지를 다룬다. 덱이라는 자료구조와, 그것을 써서 O(N²)처럼 보이는 문제를 O(N)에 푸는 기법이다. 진짜 내용은 후자다.

1.1 덱 — 양쪽이 다 열렸다

자료구조넣는 곳빼는 곳한 줄 요약
스택 (06장)뒤뒤한쪽 끝만
큐 (07장)뒤앞양쪽 끝, 방향 고정
덱 (deque)앞·뒤 둘 다앞·뒤 둘 다양쪽 끝 자유

덱은 스택이자 큐다. 뒤쪽만 쓰면 스택이고, 뒤로 넣고 앞에서 빼면 큐다. 구현도 07장 원형 큐에 두 연산을 더하면 끝난다(3.1절). 그러니 덱 자체는 이 장의 어려운 부분이 아니다.

1.2 진짜 주제 — 이중 루프를 없앤다

다음 문제를 보자. 아주 자연스러운 문제이고, 자연스러운 풀이는 이중 루프다.

오큰수 문제

수열 A가 주어진다. 각 원소에 대해 오른쪽에 있으면서 자기보다 큰 수 중 가장 왼쪽 것을 구하라. 없으면 −1. (N ≤ 1,000,000)

/* 자연스러운 풀이 — O(N²) */
for (int i = 0; i < n; i++) {
    ans[i] = -1;
    for (int j = i+1; j < n; j++)
        if (a[j] > a[i]) { ans[i]=a[j]; break; }
}

이게 왜 위험한가

무작위 입력에서는 break가 금방 걸려 빠르다. 그런데 감소 수열(10, 9, 8, …)이 들어오면 매번 끝까지 훑는다. 출제자는 그 입력을 넣는다.

원문 벤치마크 예시 · 감소 수열 n = 100,000 (환경에 따라 시간 변동)
단조 스택   :    0.4 ms  (연산     100,000회)
완전 탐색   : 1337.0 ms  (연산 4,999,950,000회)     약 3,300배

이 장에서 배울 단조 스택은 같은 문제를 O(N)에 해결한다(위 0.4 ms는 원문에 실린 실행 예시이며 기기별로 달라진다). 비결은 “더 이상 쓸모없어진 값을 버리면서 쌓는 것”이고, 그 결과 쌓인 값들이 단조 증가 또는 단조 감소 상태가 된다(같은 값이 남을 수도 있다). 그래서 이름이 단조(monotonic)다.

1.3 이 장이 어려운 이유

코드는 짧다. 어려운 것은 두 가지를 동시에 납득하는 일이다.

① 버려도 되는가

왜 어떤 값은 앞으로 영영 쓸모가 없어서 버려도 되는가 (2.4절)

② 왜 O(N)인가

while이 for 안에 있는데 왜 이중 루프가 아닌가 (4.1절)

①은 문제마다 생각해야 하고, ②는 06장 4.2절의 “많아야 한 번” 논리가 그대로 쓰인다. 이 장에서 네 번째로 만나는 셈이다.

2.2 구현의 유일한 새 조각 — push_front

07장 방식 B 원형 큐에서 push_back과 pop_front는 이미 만들었다. 새로 필요한 것은 두 개뿐이다.

연산하는 일주의
push_frontdf = (df − 1 + CAP) % CAP−1이 되므로 반드시 +CAP (07장 연습 04)
pop_backdcnt−−개수만 줄이면 맨 뒤가 떨어져 나간다

여기서 07장 연습 04가 쓰인다

2.3 단조성이란 무엇인가

이제 본론이다. 단조 스택은 특별한 자료구조가 아니다. 그냥 스택인데, 쌓을 때 규칙을 하나 더 지킬 뿐이다.

규칙

새 값을 쌓기 전에, 스택 맨 위가 “새 값에 밀려 쓸모없어졌다면” 꺼내 버린다.
그 결과 스택 안의 값들은 항상 정렬된 상태(단조 증가 또는 단조 감소)를 유지한다.

오큰수 문제라면 규칙은 이렇게 구체화된다 — 맨 위 값이 새 값보다 작으면, 그 값의 답은 바로 새 값이다. 답을 적어 주고 꺼낸다. 그 결과 스택에는 새 값보다 크거나 같은 원소의 위치만 남아, 아래쪽 값이 위쪽 값보다 크거나 같은 상태가 유지된다. 꺼낸 원소는 쓸모없어서 버리는 것이 아니라 오큰수의 답을 확정한 것이다.

2.4 왜 버려도 되는가 — 지배 관계

단조 기법의 핵심은 “이 값은 앞으로 영영 쓸모가 없다”를 확신하는 것이다. 슬라이딩 윈도우 최솟값으로 설명하면 가장 분명하다.

상황

창(window) 안의 최솟값을 계속 알아야 한다. 창은 오른쪽으로 한 칸씩 움직인다. 지금 덱 안에 위치 i의 값 5가 들어 있는데, 새로 위치 j(> i)의 값 3이 들어온다.

5가 최솟값으로 뽑힐 수 있으려면 3이 창 안에 없어야 하는데, 3은 5보다 오른쪽에 있으므로 5가 창에 있는 한 3도 반드시 창에 있다. 따라서 새 값 3을 처리한 이후의 창에서는 5가 최솟값이 될 수 없다. (이전 창의 답은 이미 계산했다.) 버려도 안전하다.

일반화 — 단조 기법을 설계하는 질문

새 값이 들어올 때마다 스스로에게 묻는다 — “맨 끝에 있는 이 값이, 새 값에 비해 모든 면에서 불리한가?”
오큰수라면 “더 왼쪽에 있고 값도 작은가”이고, 윈도우 최솟값이라면 “더 왼쪽에 있고 값도 큰가”다. 답이 예이면 버린다. 이 질문을 세울 수 있으면 단조 기법을 쓸 수 있다.

단조 스택과 단조 덱의 차이

기법버리는 곳왜 그 구조인가
단조 스택뒤(맨 위)에서만지배당한 값만 버리면 되므로 한쪽 끝이면 충분하다
단조 덱뒤에서 지배당한 값
앞에서 창을 벗어난 값		버리는 이유가 두 가지라서 양쪽 끝이 다 필요하다 — 덱이 쓰이는 이유

3.1 원형 덱

/* deque.c — 07장 방식 B를 확장한 원형 덱 (C11) */
#include <stdio.h>
#include <stdlib.h>
#define CAP 1000005
static int dq[CAP], df, dcnt;

static void d_require(int ok){
    if (!ok) { fputs("덱 범위 오류\n", stderr); exit(EXIT_FAILURE); }
}
static int d_empty(void){ return dcnt == 0; }
static int d_full (void){ return dcnt == CAP; }
static int d_size (void){ return dcnt; }

static void d_push_back(int x){
    d_require(!d_full());
    dq[(df + dcnt) % CAP] = x; dcnt++;
}
static void d_push_front(int x){
    d_require(!d_full());
    df = (df - 1 + CAP) % CAP;
    dq[df] = x; dcnt++;
}
static int d_pop_front(void){
    d_require(!d_empty());
    int x = dq[df]; df = (df + 1) % CAP; dcnt--; return x;
}
static int d_pop_back(void){
    d_require(!d_empty());
    dcnt--; return dq[(df + dcnt) % CAP];
}
static int d_front(void){ d_require(!d_empty()); return dq[df]; }
static int d_back(void){
    d_require(!d_empty()); return dq[(df + dcnt - 1) % CAP];
}
static void d_clear(void){ df = dcnt = 0; }

d_pop_back은 개수만 줄여도 된다

맨 뒤 값의 자리는 (df + dcnt - 1) % CAP이다. dcnt를 먼저 하나 줄이면 그 식이 (df + dcnt) % CAP이 되므로, 줄이고 나서 읽으면 계산이 한 번으로 끝난다. 배열에 남아 있는 값은 지우지 않는다 — 05장 vec_pop과 같은 방식이다.

총 push가 제한될 때는 선형 인덱스도 쓴다

07장 3.3절과 같다. 총 push 횟수가 적으면 % 없이 배열 가운데에서 시작해 양쪽으로 벌려 쓰는 방법이 더 간단하다. 다만 앞뒤로 얼마나 벌어질지(각 방향의 삽입 횟수)를 모르면 위험하므로, 단조 기법처럼 총 push가 N번으로 묶이는 경우에만 쓴다. 3.3절의 슬라이딩 윈도우가 그런 경우라 거기서는 선형 배열을 쓴다.

3.2 단조 스택 — 오큰수

다음 코드는 3.1절 덱 코드와 별개의 프로그램에 넣는 함수 예시다. 배열과 매크로는 최대 입력 크기에 맞춰 선언하며, 호출 전 0 <= n <= MAXN을 확인한다.

06장 도전 C1에서 미리 만난 “위치를 쌓는다”가 여기서 본격적으로 쓰인다. 값이 아니라 아직 답을 못 찾은 원소들의 위치를 쌓는다.

#define MAXN 1000005
static int a[MAXN], ans[MAXN], st[MAXN];
static int sp;

static void next_greater(int n){
    sp = 0;
    for (int i = 0; i < n; i++) {
        /* 맨 위가 a[i]보다 작으면, 그 원소의 답이 바로 a[i]다 */
        while (sp && a[st[sp-1]] < a[i])
            ans[st[--sp]] = a[i];
        st[sp++] = i;                  /* 아직 답을 못 찾았으니 쌓는다 */
    }
    while (sp) ans[st[--sp]] = -1;     /* 끝까지 남은 것은 답이 없다 */
}

추적표의 스택 열을 보자 — 1:5 2:2, 3:7 4:5. 언제나 아래 값 ≥ 위 값이다. 작거나 같은 값이 들어오면 그냥 쌓이고, 큰 값이 들어오면 자기보다 작은 것들의 오큰수를 확정하고 꺼낸다. 이 정렬 상태가 저절로 유지되는 것이 “단조”의 뜻이다.

왜 값이 아니라 위치를 쌓는가

답을 ans[]의 어느 칸에 적어야 하는지 알아야 하기 때문이다. 값만 쌓으면 “이 값이 몇 번째 원소였는지”를 잃는다. 06장 도전 C1의 괄호 짝 찾기와 완전히 같은 발상이다.

3.3 슬라이딩 윈도우 최솟값

길이 N인 수열에서 크기 k인 창을 한 칸씩 옮기며 각 창의 최솟값을 구한다. 완전 탐색은 O(N×k)다.

덱에는 위치를 담고, 두 방향에서 버린다 — 뒤에서는 지배당한 값, 앞에서는 창을 벗어난 값.

#define MAXN 1000005
#include <stdio.h>
#include <stdlib.h>
static int a[MAXN], dq[MAXN];       /* dq 에는 '위치'를 담는다 */

static void window_min(int n, int k){
    if (n < 1 || n > MAXN || k < 1 || k > n) { fputs("잘못된 n 또는 k\n", stderr); exit(EXIT_FAILURE); }
    int f = 0, r = 0;                 /* 선형으로 쓴다 (총 push가 N번) */
    for (int i = 0; i < n; i++) {
        /* ① 뒤에서 — a[i]에 지배당한 것을 버린다 */
        while (r > f && a[dq[r-1]] >= a[i]) r--;
        dq[r++] = i;
        /* ② 앞에서 — 창을 벗어난 것을 버린다 */
        while (f < r && dq[f] <= i - k) f++;
        /* ③ 창이 완성되면 맨 앞이 곧 최솟값 */
        if (i >= k-1) printf("%d ", a[dq[f]]);
    }
}

네 단계 처리 순서 — 올바른 구현의 한 예

① 뒤에서 버리고 → ② 넣고 → ③ 앞에서 버리고 → ④ 출력. 이 구현에서 사용하는 순서다. 이 순서는 올바른 구현 중 하나다. 앞에서 만료된 위치를 먼저 제거한 뒤, 뒤쪽 지배 후보를 제거하고 삽입해도 정답이며, 어느 순서든 덱이 비었을 때의 접근을 피해야 한다. 그리고 while 조건의 >=는 같은 값도 버린다는 뜻인데, 그래야 더 오른쪽 것이 남아 덱이 짧아진다.

3.4 연산 횟수와 실행 시간 예시

아래 시간은 원문에 제시된 특정 환경의 실행 예시로, 기기·컴파일러·입력에 따라 재현되지 않을 수 있다. 복잡도는 실행 시간 한 번이 아니라 원소별 삽입·삭제 횟수로 판단한다.

오큰수

감소 수열 (최악의 경우) — 오른쪽에 큰 수가 없어 완전 탐색은 끝까지 훑는다
n= 50,000 :  단조   0.2 ms (    50,000회)   완전탐색   330.7 ms ( 1,249,975,000회)
n=100,000 :  단조   0.4 ms (   100,000회)   완전탐색  1337.0 ms ( 4,999,950,000회)

무작위 수열 — 완전 탐색도 break 가 금방 걸려 빠르다
n=  100,000 : 단조  0.2 ms (  199,991회)   완전탐색   0.2 ms (    646,561회)
n=1,000,000 : 단조  3.1 ms (1,999,977회)   완전탐색   5.8 ms ( 17,354,564회)

무작위 입력으로 테스트하면 속는다

위 무작위 예시에서는 완전 탐색도 빨라 보인다(n = 100만에 5.8 ms). 이 시간은 특정 환경의 측정치이며, 무작위 입력이라고 항상 빠른 것은 아니다. 그런데 감소 수열을 넣으면 n = 10만에서 벌써 1.3초다. 02장 2.4절 — 출제자는 최악의 입력을 일부러 넣는다. “내 테스트에서는 빨랐는데요”가 변명이 되지 않는 이유다.

슬라이딩 윈도우 최솟값

n=  200,000  k=  500 :  덱  0.6 ms (  399,458회)   완전탐색   48.5 ms (  99,550,999회)
n=  200,000  k=1,000 :  덱  0.4 ms (  399,715회)   완전탐색   99.2 ms ( 198,801,999회)
n=1,000,000  k=1,000 :  덱  3.5 ms (1,999,080회)   완전탐색  505.3 ms ( 998,001,999회)

표에서 읽어야 할 두 가지

  • 덱의 삽입은 N번이고 삭제는 최대 N번이므로, 삽입·삭제 합계가 2N 이하이다. n = 20만이면 최대 40만, n = 100만이면 최대 200만. k가 500이든 1,000이든 변하지 않는다 — 창 크기와 무관하다는 것이 이 기법의 핵심이다
  • 완전 탐색의 비교 횟수는 (N−k+1)(k−1)이다. 고정된 N에서 k를 늘리면 대체로 N×k에 비례하며, 위 예시에서도 약 2배가 되었다(정확히 2배는 아님)

왜 2N인지는 다음 절에서 증명한다. 먼저 각 위치가 덱에 한 번 들어가고 많아야 한 번 나온다는 사실을 떠올려 보자.

Q. 최솟값 말고 최댓값을 구하려면요?
부등호만 뒤집는다. a[dq[r-1]] >= a[i]를 a[dq[r-1]] <= a[i]로 바꾸면 덱이 감소 상태를 유지하게 되고, 맨 앞이 최댓값이 된다. 구조는 글자 하나도 바뀌지 않는다.

4복잡도 분석

4.1 while이 for 안에 있는데 왜 O(N)인가

이 장에서 가장 중요한 논증이다. 코드만 보면 이중 루프라 O(N²)처럼 보인다.

for (int i = 0; i < n; i++) {        /* N번 */
    while (sp && ...) sp--;            /* 최악엔 N번? */
    st[sp++] = i;
}

증명 — 원소 하나의 일생을 센다

각 원소가 겪는 일평생 횟수이유
스택에 push 된다정확히 1번for문에서 i마다 한 번씩만 쌓는다
스택에서 pop 된다많아야 1번한 번 나가면 다시 들어오지 않는다
합계2N번 이하따라서 전체가 O(N)

while이 한 번에 여러 개를 꺼내는 경우는 분명히 있다. 추적표의 i = 3에서 두 개를 연달아 꺼냈다. 하지만 그만큼 다른 i에서는 꺼낼 것이 없다. 전체를 합치면 pop 횟수가 push 횟수를 넘을 수 없다.

실측이 이를 확인해 준다 — 위 예시에서 n = 100만일 때 단조 스택의 삽입·삭제 합계가 1,999,977회, 즉 정확히 2N에 거의 일치했다.

같은 논리가 반복해서 나온다

  • 05장 — Vec의 용량 2배 증가, 총 복사가 2N 이하
  • 06장 — 괄호 검사·후위 변환, 한 번 쌓인 것은 한 번만 나온다
  • 07장 C1 — 스택 두 개로 만든 큐, 한 원소는 평생 한 번만 옮겨진다
  • 08장 — 단조 스택·단조 덱 (네 번째)

4.2 연산별 비용

대상복잡도비고
덱의 네 연산O(1)용량·빈 상태 검사와 인덱스 계산. 가득 찼을 때 추가 삽입은 허용하지 않음
오큰수 (단조 스택)O(N)완전 탐색은 최악 O(N²)
윈도우 최솟값 (단조 덱)O(N)완전 탐색은 O(N×k). k와 무관하다는 것이 핵심

4.3 공간

단조 스택·덱에는 많아야 N개의 위치가 저장된다. 오큰수에서는 최대 N개가 쌓일 수 있고, 슬라이딩 윈도우의 후보는 최대 k개다. 따라서 배열은 N칸이면 충분하고, N = 100만인 int 배열 한 개는 약 4 MB(약 3.81 MiB)다.

슬라이딩 윈도우에서는 더 작다. 덱에 남는 것은 창 안에 있으면서 지배당하지 않은 값들뿐이라 많아야 k개다. 그래도 안전하게 N칸으로 잡는다 — 04장에서 배운 대로 최댓값으로 고정 선언하는 편이 실수가 없다.

예제 2 지배 관계 판단

슬라이딩 윈도우 최솟값을 구하는 중이다. 아직 창에 포함된 덱에 위치 2(값 7)와 위치 5(값 7)가 있다. 위치 7에 값 7이 새로 들어온다. (1) 앞의 둘을 버려야 하는가? (2) 조건이 >=가 아니라 >라면 무엇이 달라지는가?

  • (1) 버린다. 값이 같을 때도 더 오른쪽 것이 더 오래 남으므로 왼쪽 것은 쓸모가 없다. 최솟값이 7인 창이라면 위치 7의 7을 답으로 내면 된다
  • (2) >라면 같은 값을 안 버린다. 최솟값 자체는 여전히 맞지만 같은 값이 더 오래 남는다. 모든 값이 7인 수열에서는 덱 크기가 최대 k개가 될 수 있으며(k = N = 100만이면 100만 개), >=를 쓰면 중복 후보를 제거하여 보통 더 짧게 유지한다. 어느 쪽이든 시간복잡도는 O(N), 공간은 최악 O(k)다

정리. 최솟값만 요구할 때 >=와 >는 정답과 점근적 시간복잡도는 같고, 동점 처리 및 덱에 남는 원소 수가 달라진다. 다만 문제가 “최솟값의 위치”를 묻는다면 어느 쪽을 쓰느냐에 따라 어느 위치가 답이 되는지가 달라지므로 그때는 문제의 요구를 보고 정해야 한다.

(2) (1)의 두 값은 단조 스택으로 구할 수 있다. 무엇을 쌓고 언제 꺼내는가? 3.2절의 오큰수와 비교해 설명하라.
(3) h = [2, 1, 4, 5, 1, 3, 3]에 대해 추적표를 쓰고 답이 8임을 확인하라.

C2창 크기가 변하는 문제
수열 A와 정수 S가 주어진다. 합이 S 이상인 가장 짧은 연속 구간의 길이를 구하라. 모든 값은 양수이고 N ≤ 1,000,000.
(1) 이 문제는 창 크기가 고정이 아니다. 그런데도 O(N)에 풀 수 있다. 어떤 성질 덕분인가? (힌트 — 모든 값이 양수다)
(2) 두 포인터를 쓰는 방법을 설계하라. 오른쪽 끝을 늘릴 때와 왼쪽 끝을 줄일 때의 조건을 각각 쓰라.
(3) A = [2, 3, 1, 2, 4, 3], S = 7일 때 추적표를 쓰고 답을 구하라.
(4) 이 방법이 O(N)인 이유를 4.1절과 같은 논증으로 설명하라.
(5) 만약 음수가 섞여 있다면 왜 이 방법이 깨지는가? 반례를 하나 들어라.

두 문항이 겨냥하는 것

C1은 단조 스택의 대표 응용이다. “왼쪽·오른쪽으로 얼마나 뻗을 수 있는가”를 묻는 모든 문제가 같은 틀이고, 대회 출제 빈도가 높다. C2는 14장 투 포인터를 미리 만나는 문항으로, “포인터 두 개가 각각 한 방향으로만 움직이므로 전체 O(N)”이라는 4.1절과 똑같은 논증이 쓰인다. (5)는 그 논증이 어떤 전제 위에 서 있는지를 묻는다 — 가장 중요한 질문이다.

“단조 스택에 값을 쌓는다”답을 어느 칸에 적을지 모르게 된다위치(인덱스)를 쌓는다. 값은 a[st[sp-1]]로 본다
“while이 있으니 O(N²)”한 원소는 많아야 한 번 나간다원소 하나의 일생을 세어 본다 (4.1절)
“무작위로 테스트했더니 빠르던데”완전 탐색은 무작위에서 빠르고 최악에서만 터진다감소 수열 같은 최악 입력으로 테스트한다
“윈도우에서 앞뒤 중 하나만 버리면 되지”버리는 이유가 두 가지다 — 지배당함(뒤), 창 벗어남(앞)그래서 스택이 아니라 덱이 필요하다
“순서는 상관없겠지”뒤에서 버리기 → 넣기 → 앞에서 버리기 → 출력의 순서가 중요하다추적표로 한 번 확인하고 그 순서를 고정한다
“>=든 >든 답은 같으니까”답은 같지만 덱 길이가 달라진다. 위치를 묻는 문제면 답도 달라진다효율을 위해 >=를 쓰되, 문제가 위치를 묻는지 확인한다
