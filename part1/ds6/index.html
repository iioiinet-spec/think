1왜 필요한가

01장에서 뽑은 동사 하나 — “가장 최근에 넣은 것을 뺀다” — 가 지목하는 자료구조를 드디어 만든다.

1.1 되돌아가야 하는 일들

스택이 쓰이는 상황에는 공통점이 있다. 들어간 순서의 역순으로 빠져나와야 한다는 것이다.

상황쌓는 것왜 역순인가
괄호 짝 검사아직 짝을 못 찾은 여는 괄호가장 안쪽 괄호가 가장 먼저 닫힌다
수식 계산아직 계산하지 못한 연산자우선순위가 높은 연산이 나중에 들어와 먼저 처리된다
되돌리기(undo)지금까지 한 작업마지막에 한 일부터 취소한다
함수 호출돌아갈 자리나중에 부른 함수가 먼저 끝난다
미로 탐색(DFS)갈림길막히면 가장 최근 갈림길로 되돌아간다

마지막 두 줄이 중요하다. 컴퓨터가 함수를 부르고 돌아오는 방식 자체가 스택이고, 30장에서 배울 DFS도 스택이다. 그래서 이 장에서 “재귀를 스택으로 바꾸는 법”(3.5절)까지 다룬다.

1.2 05장을 했다면 거의 다 끝났다

05장 도전 C2에서 확인했듯, 스택의 기본 push·pop 동작은 Vec의 맨 뒤 연산과 같다.

스택 연산Vec으로는설명
pushvec_push 그대로맨 뒤가 곧 맨 위다
popvec_pop 그대로
top마지막 칸 읽기 — 새로 한 줄a[n-1]
emptyn == 0그대로

그래서 이 장의 무게는 자료구조 자체가 아니라 응용에 있다. 괄호 검사, 후위 표기, 재귀 치환 — 셋 다 대회 단골이고, 셋 다 “스택을 떠올릴 수 있는가”로 갈린다.

Q. 그냥 배열에 담고 인덱스로 관리하면 되지 않나요?
맞다. 실제로 그렇게 구현한다. 스택은 배열 하나와 정수 하나(sp)면 끝이다. 그런데도 “스택”이라는 이름을 붙이는 이유는 01장에서 배운 대로 가운데를 건드리지 않겠다는 약속을 하기 위해서다. 그 약속 덕분에 코드를 읽는 사람이 LIFO를 전제할 수 있고, 스택의 공개 연산만 사용하면 중간 조작을 피할 수 있다.

3구현

스택 본체는 짧지만 배열 용량과 비어 있는 상태에 대한 사전조건을 꼭 지켜야 한다. 나머지 절은 응용을 다룬다.

3.1 배열 스택 — 대회 실전형

대회에서는 Vec을 감싸기보다 전역 배열과 정수 하나로 쓰는 쪽이 더 흔하다. 짧고 실수가 없기 때문이다.

/* stack.c — 전역 배열 스택 */
#define MAXS 1000005
static int st[MAXS];
static int sp;                    /* 다음에 쌓을 자리 = 현재 개수 */

static void push(int x){ st[sp++] = x; }       /* 사전: sp < MAXS */
static int  pop (void){ return st[--sp]; }   /* 사전: sp > 0 */
static int  top (void){ return st[sp-1]; }   /* 사전: sp > 0 */
static int  empty(void){ return sp == 0; }
static void clear(void){ sp = 0; }            /* 여러 번 쓸 때 */
쓰는 곳어느 쪽이유
대회 문제 풀이전역 배열 스택10줄이고 메모리 관리가 없다. 크기 상한을 알 때 1순위
스택이 여러 개Vec 감싸기각자 필요한 만큼만 쓴다 (05장 예제 3)
크기를 모름Vec 감싸기필요에 따라 확장할 수 있다. 단, 메모리 할당 실패는 검사해야 한다

sp가 가리키는 자리를 헷갈리지 않기

이 교재는 sp를 “다음에 쌓을 빈 자리”로 쓴다. 그래서 현재 개수와 sp가 같고, 맨 위 값은 st[sp-1]이다. 반대로 sp를 “맨 위 값의 자리”로 쓰는 방식도 있는데, 그러면 빈 상태가 sp == -1이 되고 push는 st[++sp]가 된다. 둘 다 맞지만 섞어 쓰면 반드시 틀린다. 한 가지로 통일한다.

배열 크기와 사용 조건

괄호 검사에서는 최대 열린 괄호 수, DFS에서는 구현 방식에 따른 최대 동시 대기 정점 수를 기준으로 정한다. 예제의 push는 sp < MAXS, pop/top은 sp > 0이 사전조건이다. 큰 배열은 전역이나 동적 할당을 사용하면 호출 스택 부담을 줄일 수 있다.

3.2 응용 ① 괄호 짝 검사

01장 3.2절에서 동사를 뽑아 둔 그 문제다. 이번에는 세 종류 괄호 () [] {}가 섞인다.

static char match(char c){            /* 닫는 괄호의 짝 */
    return c == ')' ? '(' : (c == ']' ? '[' : '{');
}
static int balanced(const char *s){
    sp = 0;
    for (const char *p = s; *p; ++p) {
        if (*p=='(' || *p=='[' || *p=='{') push(*p);
        else if (*p==')' || *p==']' || *p=='}') {
            if (empty())            return 0;   /* 닫는데 열린 게 없다 */
            if (top() != match(*p)) return 0;   /* 종류가 다르다 */
            pop();
        }
    }
    return empty();                        /* 남은 게 없어야 올바르다 */
}
$ ./bracket
(())()       -> 올바름
())(         -> 틀림        닫는데 열린 게 없음
([{}])       -> 올바름
([)]         -> 틀림        종류가 어긋남
(((          -> 틀림        끝났는데 남아 있음
(빈 문자열)  -> 올바름
a(b[c]d)e    -> 올바름      괄호 아닌 글자는 무시

틀리는 경우가 정확히 세 가지다

  1. 닫는데 스택이 비었다 — ())(의 세 번째 글자
  2. 맨 위와 종류가 다르다 — ([)]의 ). 맨 위는 [인데 짝이 (라서 어긋난다
  3. 다 읽었는데 남아 있다 — (((

종류별로 스택 세 개를 쓰면 왜 틀리는가

소괄호용·대괄호용·중괄호용 카운터를 따로 두면 ([)]가 올바르다고 판정된다. 소괄호도 1개씩, 대괄호도 1개씩 맞기 때문이다. 하지만 “열린 순서의 역순으로 닫혀야 한다”는 조건은 종류를 가로질러 확인해야 하므로, 하나의 스택에 모두 쌓아야 한다. 이 반례 하나로 설계가 결정된다.

입력 조건: 문자열 길이는 스택 용량 MAXS 이하로 제한한다. 더 긴 입력을 허용한다면 push 전에 용량 검사 또는 동적 확장이 필요하다.

3.3 응용 ② 중위 → 후위 표기

우리가 쓰는 A+B*C는 중위 표기다. 연산자가 가운데 있어 우선순위와 괄호를 따져야 한다. 후위 표기 ABC*+는 계산 순서가 표현에 반영되므로 계산할 때 별도로 괄호·우선순위를 해석하지 않아도 된다.

중위후위읽는 법
A+B*CABC*+B와 C를 곱하고, 거기에 A를 더한다
(A+B)*CAB+C*A와 B를 더하고, 거기에 C를 곱한다

변환 규칙은 세 줄이다. 피연산자는 바로 내보내고, 연산자는 스택에 쌓되 괄호 밖에서 자기보다 우선순위가 같거나 높은 연산자는 먼저 내보낸다(여기서는 모두 왼쪽 결합). 여는 괄호는 그냥 쌓고, 닫는 괄호를 만나면 여는 괄호가 나올 때까지 쏟아 낸다.

static int prec(char c){            /* 우선순위 */
    return (c=='*'||c=='/') ? 2 : (c=='+'||c=='-') ? 1 : 0;
}
static void to_postfix(const char *s, char *out){
    int k = 0;  sp = 0;
    for (const char *p = s; *p; ++p) {
        if (*p == ' ' || *p == '\\t') continue;
        if (*p >= 'A' && *p <= 'Z') out[k++] = *p;      /* 피연산자 */
        else if (*p == '(') push(*p);
        else if (*p == ')') {
            while (!empty() && top() != '(') out[k++] = pop();
            if (!empty()) pop();                       /* '(' 는 버린다 */
        } else {
            while (!empty() && top() != '(' &&
                   prec(top()) >= prec(*p))
                out[k++] = pop();
            push(*p);
        }
    }
    while (!empty()) out[k++] = pop();          /* 남은 것 쏟기 */
    out[k] = '\0';
}
$ ./postfix
A+B*C          -> ABC*+
(A+B)*C        -> AB+C*
A*B+C*D        -> AB*CD*+
A+B*C-D/E      -> ABC*+DE/-
((A+B)*C-D)*E  -> AB+C*D-E*

이 예제의 입력 범위: 피연산자는 영문 대문자 한 글자, 연산자는 + - * /, 괄호는 올바르게 짝지어져 있으며 단항 마이너스는 없다. 출력 배열은 strlen(s)+1바이트 이상이어야 한다. 문법 오류 검사는 실전 프로그램에서 별도로 추가한다.

왜 >=인가 (>가 아니라)

같은 우선순위일 때도 먼저 내보내야 왼쪽부터 계산된다. A-B-C는 (A-B)-C이지 A-(B-C)가 아니다. >로 쓰면 ABC--가 되어 뺄셈 순서가 뒤집힌다. 거듭제곱처럼 오른쪽부터 계산하는 연산자라면 반대로 >를 쓴다.

3.4 응용 ③ 후위 표기 계산

변환보다 훨씬 쉽다. 숫자는 쌓고, 연산자를 만나면 두 개를 꺼내 계산해 다시 쌓는다. 끝나면 스택에 하나가 남고 그것이 답이다.

/* 한 자리 숫자 후위식. 성공 1 / 실패 0 */
#include <limits.h>
static long long val[MAXS];
static int vsp;
static int eval_postfix(const char *s, long long *answer){
    vsp = 0;
    for (const char *p=s; *p; ++p) {
        if (*p==' ' || *p=='\t') continue;
        if (*p>='0' && *p<='9') {
            if (vsp>=MAXS) return 0;
            val[vsp++]=*p-'0'; continue;
        }
        char op=*p;
        if (op!='+' && op!='-' && op!='*' && op!='/') return 0;
        if (vsp<2) return 0;
        long long b=val[--vsp], a=val[--vsp];
        if (op=='/' && (b==0 || (a==LLONG_MIN && b==-1))) return 0;
        /* 전제: 계산 결과는 모두 long long 범위 안 */
        val[vsp++]=op=='+' ? a+b : op=='-' ? a-b : op=='*' ? a*b : a/b;
    }
    if (vsp!=1) return 0;
    *answer=val[0]; return 1;
}

호출 예: long long ans; if (eval_postfix("34+2*", &ans)) printf("%lld", ans);. 이 함수는 입력 오류와 0으로 나누기를 검사한다. 범위를 벗어나는 정수 연산은 문제의 입력 조건에서 제외해야 하며, 일반 입력을 다룰 때는 별도 오버플로 검사를 추가한다. 숫자 여러 자리와 음수 리터럴은 지원하지 않는다.

$ ./postfix
34+2*    = 14        (3+4)*2
52-3*    = 9         (5-2)*3
123*+    = 7         1+(2*3)
92/4-    = 0         (9/2)-4 = 4-4, 정수 나눗셈

꺼내는 순서가 거꾸로다 — 가장 흔한 버그

a - b를 계산할 때 먼저 꺼낸 것이 오른쪽 피연산자 b다. 나중에 꺼낸 것이 왼쪽 a다. 순서를 바꾸면 덧셈·곱셈은 우연히 맞고 뺄셈과 나눗셈만 틀린다. 그래서 34+2*로 테스트하면 통과하고 52-3*에서 비로소 드러난다. 테스트는 반드시 뺄셈을 포함해야 한다.

3.5 응용 ④ 재귀를 스택으로 바꾸기

함수를 부르면 돌아갈 자리와 지역 변수가 스택(03장 2.2절)에 쌓인다. 즉 재귀는 일반적으로 컴퓨터가 호출 스택을 사용하게 하는 것이다. 호출 스택 한도는 운영체제·채점 환경·컴파일 옵션에 따라 달라지며 항상 8MB인 것은 아니다.

/* 1부터 n까지 더하는 재귀 */
static long long rec(int n){
    if (n == 0) return 0;
    return n + rec(n - 1);
}
환경별 관찰 예시 (Linux, 호출 스택 제한 8 MiB)
-O0 : 깊이가 커지면 호출 스택 한도를 넘을 수 있음
-O2 : 컴파일러가 단순 재귀를 반복 형태로 최적화할 수 있음
※ 실패하는 정확한 깊이와 최적화 여부는 보장되지 않는다.

최적화에 따라 결과가 달라질 수 있다

-O2에서는 특정 재귀가 반복문으로 최적화될 수 있다. 그러나 모든 재귀가 그렇게 바뀌는 것은 아니다. 가지가 갈라지는 호출이나 작업이 남아 있는 호출은 스택을 계속 사용할 수 있다. 같은 코드라도 컴파일러·환경에 따라 한계가 달라진다. 깊이가 매우 큰 문제는 명시적 스택이나 반복문으로 해결하는 편이 안전하다.

명시적 스택으로 바꾸기

“호출을 쌓는” 대신 “해야 할 일을 쌓는다”로 바꾸면 전역 배열을 쓰게 되어 8MB 제한에서 벗어난다. DFS를 예로 보자.

/* 재귀 DFS */
void dfs(int u){
    vis[u] = 1;
    int v = nxt[u];
    if (v != -1 && !vis[v])
        dfs(v);
}
/* 명시적 스택 DFS */
st[sp++] = 0;
while (sp) {
    int u = st[--sp];
    if (vis[u]) continue;
    vis[u] = 1;
    int v = nxt[u];
    if (v != -1 && !vis[v]) st[sp++] = v;
}
명시적 스택 DFS는 함수 호출 스택의 깊이 제한을 피한다.
※ 정점 수에 맞게 vis/nxt를 할당하고, 대기 정점 수에 맞는 스택 용량도 확보해야 한다.

바꾸는 세 단계

  1. 쌓을 것을 정한다 — 단순 DFS는 정점 번호를 쌓는다. 복잡한 재귀는 지역 상태·복귀 단계도 담아야 할 수 있다
  2. while (sp) 루프로 감싼다 — 꺼내서 처리하고, 다음에 할 일을 쌓는다
  3. 방문 검사의 시점을 정한다 — 이 예제는 꺼낼 때 검사하지만, 일반 그래프는 중복 push 방지를 위해 넣을 때 표시하기도 한다

※ 함수가 끝난 뒤에 할 일이 있는 재귀(후위 순회 등)는 바꾸기가 더 까다롭다. 16장 이진 트리에서 그 방법을 따로 다룬다.

예제 4 재귀를 스택으로

다음 재귀를 명시적 스택으로 바꿔라. 깊이가 100만까지 갈 수 있다.

void walk(int u){
    if (u > n) return;
    visit(u);
    walk(u + 1);
}

풀이. 3.5절의 세 단계를 적용한다. ① 쌓을 것은 매개변수 u ② while (sp)로 감싼다 ③ 꺼낸 직후에 조건을 확인한다.

sp = 0;  st[sp++] = 1;
while (sp) {
    int u = st[--sp];
    if (u > n) continue;        /* 재귀의 종료 조건이 여기로 */
    visit(u);
    st[sp++] = u + 1;              /* 재귀 호출이 여기로 */
}

생각할 점. 이 경우는 사실 스택이 필요 없다. 쌓이는 것이 항상 하나뿐이라 for (u = 1; u <= n; u++) visit(u);로 충분하다. 가지가 하나뿐인 재귀는 그냥 반복문이고, 여러 갈래를 탐색하거나 복귀 후 할 일이 남는 경우에는 상태를 보관하는 명시적 스택이 도움이 된다 — 16장 이진 트리 순회와 30장 DFS에서 활용한다.

흔한 생각무엇이 틀렸나바로잡기
“빈 스택에서 pop해도 괜찮겠지”빈 스택에서 st[--sp]에 접근하면 정의되지 않은 동작이다. 오류 종료 또는 잘못된 결과가 발생할 수 있다꺼내기 전에 empty()를 확인한다. 01장 명세표의 사전조건 그대로

  • 중위 → 후위 변환을 손으로 추적할 수 있다
  • 후위 계산에서 먼저 꺼낸 값이 오른쪽 피연산자임을 안다
  • 재귀를 명시적 스택으로 바꾸는 세 단계를 적용할 수 있다
  • “가장 최근 것부터”라는 말을 들으면 스택을 떠올린다

다음 장 예고 — 07 큐와 원형 큐

스택이 “가장 최근”이었다면 큐는 “가장 먼저”다. 한쪽 끝에서 넣고 반대쪽 끝에서 뺀다. 그런데 이 한 글자 차이가 구현을 꽤 바꿔 놓는다. 앞에서 빼면 빈자리가 앞에 생겨 배열이 금방 소진되기 때문이다. 해결책이 원형 큐이고, 거기서 “가득 참과 비어 있음을 어떻게 구별하는가”라는 유명한 문제를 만난다. 30장 BFS가 전부 이 큐 위에서 돈다.
